В ReWrite-конвейере **единый реестр макросов** — в `prompt_placeholders.py`. Других «официальных» `{{…}}` для промтов там нет.

## Все 6 макросов

| Макрос | Откуда значение | Как подставляется |
|--------|-----------------|-------------------|
| `{{LANGUAGE}}` | Язык конвейера (слайдер) | Одна строка: `Русский`, `English`, `Spanish`, `Japanese` |
| `{{DURATION}}` | Слайдер Duration / `target_chars` | **Только число** символов, напр. `12000` |
| `{{TARGET_CHARS}}` | То же, что Duration | **То же число**, что и `{{DURATION}}` |
| `{{ORIGINAL_TITLE}}` | Поле «Исходное название» | Одна строка, без переносов |
| `{{MASTER_PROMT}}` | Master Promt проекта | Текст Master; если не пусто — с `\n\n` до и после |
| `{{HERO_PROMT}}` | Hero Promt проекта | То же для Hero |

Подстановка идёт в рантайме через `rewrite_placeholder_apply_from_request` → `apply_prompt_placeholders` (locked System/User, промты этапов, Master/Hero и т.д.). В файлах на диске остаются литералы `{{…}}`.

## Ещё что встречается, но это не тот же механизм

**`{{INPUT_TEXT}}`** — есть в `locked_prompt_files/translate_to_ru.txt`, но **не обрабатывается** `apply_prompt_placeholders`. При переводе Source/RU текст уходит **отдельным user-сообщением**; в system-промте этот токен, скорее всего, так и остаётся в тексте (или просто как напоминание в шаблоне).

**`{{ ORIGINAL_TITLE }}`** (с пробелами) — подставляется **только** в отдельной логике Title Strategist в `rewrite_pipeline.py`, не во всех промтах.

## Где работают

- Locked **System** / **User** и **System Rules** этапов ReWrite  
- Промты этапов на странице (через `subp()` при запуске)  
- Master/Hero **внутри** других промтов — да, если не отключено  

**Ограничение:** при `allow_nested_master_hero=False` (например, разбор самого Master/Hero) **`{{MASTER_PROMT}}` и `{{HERO_PROMT}}` не разворачиваются**; остальные четыре — подставляются.

Итого: **полный список — ровно ваши шесть**; отдельного седьмого макроса в общем движке нет, кроме особого случая `{{INPUT_TEXT}}` в переводе (фактически не используется как подстановка).

## 1. `allow_nested_master_hero=False` — это не настройка в UI

В интерфейсе, в `.env` или в шаблоне проекта **такого переключателя нет**. Это только параметр Python внутри движка подстановок.

**Где реально используется:**

| Место | Значение | Зачем |
|--------|----------|--------|
| `compose_rewrite_openai_request_body` в `rewrite_pipeline.py` | `False` только для **самих** полей Master и Hero перед вставкой в другие промты | Чтобы не было рекурсии: Master с `{{HERO_PROMT}}` → Hero с `{{MASTER_PROMT}}` → … |
| Там же функция `subp()` | `True` | Все locked/system/user промты этапов, включая `{{MASTER_PROMT}}` / `{{HERO_PROMT}}` |
| Все вызовы из `app.py` (`rewrite_placeholder_apply_from_request(...)`) | по умолчанию **`True`** | Перевод, semantic, export и т.д. — Master/Hero **разворачиваются** |

То есть ограничение «без Master/Hero» — это **внутренний шаг при подготовке текста Master/Hero**, а не режим «какой-то этап отключён».

Раньше в документации упоминали Scene Writer / Past Prompt с `allow_nested_master_hero=False` — **в текущем `app.py` таких вызовов нет** (Past in Prompt уже убран). Для обычного запуска этапов всё идёт через `subp()` с полным набором из шести макросов.

---

## 2. `{{ ORIGINAL_TITLE }}` с пробелами — зачем и нужно ли

**В общем движке** (`prompt_placeholders.py`) обрабатывается **только** `{{ORIGINAL_TITLE}}` без пробелов.

Вариант **с пробелами** остался только в двух функциях Title Strategist в `rewrite_pipeline.py`:

```501:501:srv/json_video/rewrite_pipeline.py
    up = up.replace("{{ORIGINAL_TITLE}}", repl).replace("{{ ORIGINAL_TITLE }}", repl)
```

```514:514:srv/json_video/rewrite_pipeline.py
    s = s.replace("{{ORIGINAL_TITLE}}", val_disp).replace("{{ ORIGINAL_TITLE }}", val_disp)
```

Исторически это «на всякий случай»: если в промте набрали `{{ ORIGINAL_TITLE }}` с пробелами, `subp()` это **не** заменит, а эти функции — заменят.

В ваших locked-файлах везде нормальный токен без пробелов, например в `user_prompt_title_strategist.txt` — `{{ORIGINAL_TITLE}}`.

**Практически:** отдельный вариант с пробелами **не нужен**, если договориться писать только `{{ORIGINAL_TITLE}}`. Дублирование можно убрать: один раз научить `apply_prompt_placeholders` понимать пробелы внутри `{{ … }}` (или выкинуть второй `.replace` в Title Strategist).

Для Title Strategist title всё равно попадает в user **дважды** по смыслу: через `subp(up_txt)` (уже подставляет title) и через `build_title_strategist_user_message` / `apply_title_strategist_original_title_to_user_json` (ещё раз + строка «Исходное название видео…»). Вариант с пробелами к этому не привязан — это просто запасной синтаксис.

Если хотите, могу сделать маленький PR: убрать `{{ ORIGINAL_TITLE }}` и/или свести подстановку title к одному месту в `prompt_placeholders.py`.

Строка открыта двойной кавычкой `"`, а закрыта **одинарной** `'` — для JSON это невалидно. Из‑за одной такой строки **весь** объект не парсится, и проверка остаётся в ожидании.

Нужно так:

```json

```

| Место | Когда |
|--------|--------|
| **Block Writer** | Сразу при разборе JSON каждого блока (`text`, `short_summary`) |
| **Rewrite** | При очистке результата стрима |
| **Редакторы** (Retention, Voiceover и др.) | В `edited_text` перед сохранением |
| **Чтение `full_text.txt`** | Перед передачей в Retention Editor |
| **Браузер** | При завершении этапа и при открытии страницы — старый Result тоже чинится и сохраняется |

Пример:  
`...жильё.<br><br>А теперь...` →  
`...жильё.\n\nА теперь...`

---

## 1. Покрытие сцен (главное)

| Проверка | Зачем |
|----------|--------|
| **Сколько сцен получили тайминг** | `N с таймингом / M сцен` — базовый OK/FAIL |
| **Сцены без совпадения** | `match_ratio` &lt; порога (у вас уже 0.85 → `low_confidence`) — список `scene_id` |
| **Пустой текст сцены** | тайминг «из воздуха» (интерполяция между соседями) — WARN |
| **Текст есть, совпадений 0** | явный FAIL с указанием сцены |

Это прямо отвечает на «все ли сцены нашли» и «сколько слов сопоставили».

---

## 2. Порядок и «путь» по таймлайну

Не путь к файлам, а **путь по шкале времени и по массиву words**:

| Проверка | Зачем |
|----------|--------|
| **Монотонность** | `start_ms[i] ≤ end_ms[i]`, `end_ms[i] ≤ start_ms[i+1]` (после разреза пауз) |
| **Перекрытия сцен** | две сцены на одном отрезке — FAIL |
| **Большие дыры между сценами** | пауза между `end` и следующим `start` &gt; N с — WARN (речь vs тишина) |
| **Первый / последний кадр** | первая сцена близко к 0, последняя — к `total_duration_ms` / последнему слову |
| **Неотмеченные слова** | слова в words.json вне объединения интервалов сцен — «хвост» вступления/концовки |

Порядок сцен в JSON и порядок на таймлайне должны совпадать; если `scene_id` перепутаны — отдельная проверка уникальности и соответствия карточкам на странице.

---

## 3. Статистика (то, что вы назвали + полезное)

Показывать как **сводку**, не обязательно как FAIL:

- **Средняя / медианная / min / max длительность сцены** (с)
- **Среднее число токенов на сцену** и **средний `match_ratio`**
- **Доля сцен с `low_confidence`**
- **Суммарная длительность сцен** vs длительность озвучки (не обязаны совпасть 1:1 из‑за пауз, но сильный разрыв — WARN)
- **Количество сцен** vs строк в JSON-коде / карточек в UI

Это быстро показывает «нормальный ли монтаж»: все по 0.3 с или одна на 2 минуты.

---

## 4. Согласованность источников

| Проверка | Зачем |
|----------|--------|
| **Источник Eleven vs Whisper** | после смены источника — пересчитали; в проверке писать, откуда считали |
| **Текст сцен vs озвучка** | грубо: сумма токенов сцен vs число «чистых» слов в words (не дублировать детальную проверку words, только «хватает ли слов на все сцены») |
| **Совпадение с проверкой words** | если у Eleven/Whisper `data-scenes-ok=0`, здесь тоже WARN: «источник слов не прошёл проверку» |

---

| Проверка | Зачем |
|----------|--------|
| **Все `scene_id` из карточек есть в таймингах** | и наоборот |
| **Поля NDJSON** | у каждой сцены есть `start_time_ms`, `Duration`, согласованы с `audio_timing` на карточке |

Как у Scene Writer / words:

```html
<script type="application/json" ...></script>
