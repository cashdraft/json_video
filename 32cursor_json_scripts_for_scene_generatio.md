**Cursor**

Вот полный разбор того, как `_split_text_into_translation_batches` режет текст. Это чистая работа с **символами**, без токенизаторов, без вызова OpenAI — просто чтобы каждый отрезок не превышал заданного лимита и резался в «удобной» точке.

### Параметры
- **`max_chars`** — жёсткий лимит длины одного батча. Сейчас задано **`5000`** в `app.py` (вызов в роуте `/rewrite/<id>/translate-source-ru`).
- **`lookback`** — глубина «зоны поиска удобной границы» в конце текущего окна, считается как `min(1600, max_chars // 2)`. При `max_chars = 5000` это **`1600`** символов.

### Шаги
1. **Быстрые случаи**:
   - Если текст пустой/из пробелов — возвращается `[]`.
   - Если длина текста **≤ `max_chars`** — это один батч, делить не нужно: `[t]`.
2. Дальше идём окнами от позиции `start` (начинаем с `0`):
   - Если **остаток** текста (`n - start`) **≤ `max_chars`** — это финальный батч, добавляется как есть, цикл завершается.
   - Иначе берётся **окно** `chunk = t[start : start + max_chars]` ровно длиной `max_chars`.
3. **Поиск точки разреза** идёт от конца `chunk`, в зоне последних `lookback` символов (это `tail`):
   - Сначала ищется **двойной перенос строки** `"\n\n"` (граница абзаца) — `tail.rfind("\n\n")`. Нашли — режем сразу после `\n\n`.
   - Если не нашли — ищем **одиночный перенос** `"\n"` — `tail.rfind("\n")`. Нашли — режем сразу после `\n`.
   - Если переносов нет в `tail` — fallback‑ы по всему окну `chunk`:
     - **Конец предложения** — `chunk.rfind(". ")` — режем после `". "` (точка + пробел).
     - **По пробелу** — `chunk.rfind(" ")`, причём только если найденная позиция **> `max_chars // 3`** (т.е. ≥ ~1666 симв.). Это защита: иначе при «слитном» тексте без пробелов можно случайно отрезать крохотный батч.
   - Если ничего из этого не подошло (текст без переносов/пробелов внутри окна, что почти не бывает) — режем **жёстко** по `max_chars` (`split_off = len(chunk)`).
4. **Запись батча**: берётся `t[start : start + split_off]` и у него отрезаются хвостовые `\n` (`rstrip("\n")`). Если результат непустой — добавляется в `batches`.
5. **Продвижение вперёд**: `start += split_off`, после чего пропускаются ведущие **пробелы/переносы/табы** у нового начала, чтобы батчи начинались с «значащего» символа и не дублировались переносы абзаца.

### Что значит «не больше N символов»
Лимит **`5000`** — это **верхняя граница длины каждого батча в `len(str)` Python**. То есть это символы Unicode, а не байты и не токены OpenAI. Реально батчи получаются **меньше** или **равны** `5000`:
- Если в зоне `lookback` (последние 1600 символов окна) есть `\n\n`/`\n` — батч может оказаться **3400–5000** символов (всё, что выше границы).
- Если переносов в `lookback` нет, но есть `". "`/пробел в `chunk` после трети окна — длина 1666–5000.
- Жёсткая отсечка ровно по 5000 — крайний случай.

### Что отправляется в OpenAI на каждом батче
- **system** — твой большой промпт переводчика (`REWRITE_SOURCE_RU_TRANSLATE_SYSTEM_PROMPT`).
- **user** — строка вида:
  ```
  ТЕКСТ ДЛЯ ПЕРЕВОДА:
  
  <фрагмент_батча>
  ```
- Модель — берётся из глобального селекта «Модель OpenAI для этапов» (или из `rw["model"]` / `analysis.model` как запасной).
- Запросы идут **последовательно** через `iter_rewrite_completion` (один HTTP per chunk). Затем все ответы конкатенируются: `"".join(parts).strip()` — без дополнительных разделителей; то есть переводы соседних батчей слипаются в финальный текст в том же порядке.

### Лимит можно изменить
Если хочешь батчи покрупнее/помельче — в `app.py` в роуте `rewrite_translate_source_ru` поменяй вызов:
```python
batches = _split_text_into_translation_batches(source_text, 5000)
```
например на `4000` или `6000`. Можно вынести в `.env` (если захочешь — скажи, добавлю переменную `REWRITE_TRANSLATE_RU_BATCH_CHARS`).
